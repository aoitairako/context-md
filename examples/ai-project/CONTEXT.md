# CONTEXT.md - AI Knowledge Engine

> **consciousness_level**: Intelligence layer owned by the user
> **version**: v1.0.0

## PROJECT_CONTEXT

```yaml
why: |
  AI tools are powerful but ephemeral — they change APIs, pivot business
  models, or shut down. Users who build workflows around a single AI
  vendor risk losing everything when the vendor changes.

  This project exists to invert that dependency: the user owns the
  intelligence layer (knowledge extraction, analysis, search), and
  AI clients are replaceable consumers that connect via standard protocols.

aims: |
  To create an AI-agnostic knowledge engine where:
  - The user's knowledge, patterns, and insights persist across AI vendors
  - Any MCP-compatible AI client can access the engine
  - No single AI vendor lock-in exists
```

## CONSCIOUSNESS_LEVEL

```yaml
level: "Self-sustaining intelligence"

meaning: |
  This project operates at the level of self-sustaining architecture.
  It does not fight against AI vendors (that would be reactive/fearful).
  Instead, it simply provides a complete, self-contained intelligence
  layer that works with any AI — now and in the future.

  Design decisions are guided by:
  - Completeness: the engine works independently of any AI client
  - Openness: standard protocols (MCP) over proprietary APIs
  - Persistence: user data and knowledge survive vendor changes
```

## RELATIONSHIP

```yaml
ecosystem:
  mcp: "Model Context Protocol — the standard interface for AI tools"
  ai_clients: "Claude, Gemini, Continue, Cursor — all replaceable consumers"
  user_data: "Local storage (NAS, filesystem) — canonical source of truth"

hierarchy:
  above: "The user's broader digital ecosystem"
  this: "Knowledge engine — intelligence layer"
  below: "Individual AI clients that consume this engine's tools"

design_philosophy: |
  Traditional: User's Data → Vendor's System → Vendor's AI
  This project: Any AI → MCP → This Engine → User's Data

  AI clients are interchangeable. The engine persists.
```

## DESIGN_PRINCIPLES

```yaml
principles:
  - name: "Inverted Ownership"
    meaning: "User owns the intelligence layer, AI is a replaceable client"

  - name: "Protocol over Platform"
    meaning: "Connect via MCP standard, not proprietary APIs"

  - name: "Persistence over Convenience"
    meaning: "User's knowledge must survive any vendor change"

  - name: "Peer Model"
    meaning: "This engine is one tool among peers, not a master system"
```
